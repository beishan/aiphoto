# 网络图片采集与整理入库方案

状态：第一期静态 HTML 闭环已于 2026-09-10 实现，后续增强项保留在本文路线图中。

当前版本已经实现网站基础配置与解析规则分离、每网站多规则及单一生效规则、站点级最小请求间隔、每日定时增量发现、跨任务详情链接去重、详情页/图片 URL 包含排除条件、列表与首个详情页两级预览、列表分页发现、图片页清单分页搜索与人工排除、按详情链接查看图片结果、链接清单确认、详情分页、常见懒加载属性与 `srcset`、图片下载及缩略图、永久图片跳过清单与独立管理页、独立待整理区、状态筛选与分页、跨分页 MD5 精确重复判定、可调阈值相似图分组、图库及回收站重复提示、删除恢复、批量备注、入库预检、入库时设置相册/标签、来源保留、可恢复导入批次和逐项结果、导入请求幂等、单项失败隔离、临时网络错误指数退避重试及 `Retry-After`、数据库任务领取租约与心跳、租约到期自动接管、任务暂停/继续/取消/重试、重启恢复、任务永久清理、多 HTTP 代理优先级与故障切换、URL 哈希去重、规则快照和基本出站地址防护。入口位于应用 Dock 的“网络采集”，全局网络参数位于系统设置的“爬虫设置”。

### 目标站点适配

“新增采集网站”弹窗提供 t66y 图片版预设。该预设只发现普通主题区的 `/htm_data/.../16/*.html` 帖子，分页只跟随文字为“下一頁”的链接；详情页仅从首帖 `#conttpc` 提取图片，优先读取站点实际使用的 `ess-data` 属性。预设中的页面域名请求间隔为 10 秒，以遵循目标站点 `robots.txt` 的 `Request-rate: 1/10`；第三方图片域名仍应用系统全局限速。图床域名可能随帖子和时间变化，规则预览若发现新域名，应由管理员确认后加入站点允许域名，系统不会自动扩大出站白名单。

尚未实现的增强项包括 JavaScript 浏览器渲染、robots 完整语义、单任务内部的并行页面领取及 DNS 绑定级的重绑定防护。待整理区已支持 64 位差异哈希、可调汉明距离阈值和持久化相似组，结果只供人工选择，不会自动删除。采集任务和导入批次都通过数据库租约避免多实例重复执行，并支持执行节点退出后的到期接管；仍应只采集用户有权下载且目标网站允许自动访问的公开页面。

## 1. 目标与核心流程

新增“网络采集”功能：用户指定网站入口和图片页发现规则，系统先收集符合规则的图片网页链接，再逐页提取并下载图片。下载结果进入独立的待整理区，用户去重、删除、归类后，选择图片入库。

```text
网站入口 + 规则预览
        ↓
阶段一：遍历列表/分页，收集图片页链接并去重
        ↓
链接清单确认（默认停在此处，可配置自动继续）
        ↓
阶段二：逐个图片页提取图片地址 → 下载 → 校验 → 本地缩略图
        ↓
待整理区：按页面分组 / 精确去重 / 相似图检查 / 删除 / 归类
        ↓
选择入库 → 入库结果 → 正式图库 → 本地 AI 索引
```

“全部”的范围是规则允许且从入口可达的页面和图片，不保证覆盖网站隐藏、登录后或无法访问的内容。达到数量、深度、流量或时间上限时，显示“达到限制，采集未完整”，不能提示全部完成。

## 2. 与当前项目的关系

根据当前代码：

- `PhotoService.uploadPhoto()` 和 `FolderService.importImage()` 会创建 `Photo` 并触发 AI 索引，不能直接作为采集下载入口。
- `photos` 已有 MD5、pHash、软删除时间等字段；现有去重服务面向图库记录，需要抽出可用于待整理区的计算与匹配能力。
- `AiTask` 目前面向索引、训练等 AI 任务，没有爬取阶段、暂停、租约等字段。采集任务应独立持久化，可接入现有任务展示和 WebSocket 通知模式。
- 本地存储使用照片和缩略图目录及哈希分片。新增 staging 目录，禁止与图库目录混用，也不能被目录扫描自动导入。

本次仅编写方案，不修改应用行为或版本号。功能实施时建议按新增功能递增次版本号，并同步各服务构建元数据。

## 3. 产品界面

新增一级入口“网络采集”，包含三个页面。

### 3.1 网站与规则

输入网站名称、一个或多个起始列表页、允许的页面域名与图片域名，配置图片页链接、分页及图片提取规则。规则可保存为模板，每次任务保存独立快照；修改模板不会改变正在运行的任务。

提供“测试规则”：抓取一个列表页，展示匹配的图片页 URL、标题及命中原因；再选择一个图片页，展示提取到的图片地址、使用的属性、过滤原因和有限数量的预览。无匹配时展示诊断信息，不直接启动长任务。

第一期使用表单配置 CSS 选择器与 URL 过滤条件，附带常见示例；高级 JSON 编辑可后续补充，不允许执行用户输入的脚本。

### 3.2 采集任务与链接清单

展示发现阶段、下载阶段各自的进度、成功/失败/跳过计数、累计字节、限制命中原因，以及逐页错误日志。

发现结束后可搜索、筛选、取消勾选图片页，确认后开始下载；也可在创建任务时明确选择发现完成后自动下载。发现有失败时清单标记为“不完整”，用户可重试失败项或接受当前清单继续。

支持暂停、继续、取消、重试失败项。取消停止新工作，保留已经完成的清单和文件，清理任务数据是单独操作。

### 3.3 待整理区

卡片显示本地缩略图、尺寸、大小、来源页面、重复标记和入库状态。支持按任务、页面、域名、尺寸、格式、重复类型筛选；按来源页面分组浏览和多选。

主要操作：

- 精确去重：展示重复组，默认推荐保留一张，不自动删除。
- 图库重复检查：分别标记“图库已有”和“图库回收站已有”。
- 相似图检查：给出相似组和尺寸差异，由用户决定保留项。
- 删除：移到采集区自己的已删除列表，可恢复；永久清理需明确操作。
- 整理：设置显示名称、备注、目标相册与标签，按页面批量应用。
- 选择入库：展示将新增、跳过重复、阻止入库的数量，确认后执行。

采集完成本身不会新增图库照片、人物、时间线或 AI 任务。首期“处理”聚焦去重、删除和归类，裁剪、旋转、水印等图像编辑不纳入首期。

## 4. 规则定义

### 4.1 图片页链接发现

将“允许继续遍历的列表页”和“要下载图片的详情页”分开定义，避免把详情页的推荐链接扩展成无限爬取。

| 配置 | 作用 |
| --- | --- |
| 起始 URL 列表 | 从一个或多个分类、列表入口开始 |
| 详情链接选择器 | 如 `.gallery-list a.item`，提取 `href` |
| 详情 URL 包含/排除条件 | 限制路径，排除登录、广告等链接 |
| 下一页选择器 | 如 `a.next`，递归发现列表分页 |
| 遍历链接选择器（可选） | 进入子分类等列表页；单独配置 URL 范围 |
| 页码模板（可选） | 明确起止页码，替代下一页模式，不默认同时启用 |
| 限制 | 最大列表页、详情页、遍历深度、任务时长 |

相对 URL 按最终响应地址和合法的 HTML base 地址解析，解析后仍须通过域名和网络访问检查。去掉 fragment，规范化主机名与默认端口；默认保留查询参数及其值，不擅自删除鉴权签名或重排可能参与签名的参数。追踪参数仅按显式配置移除。

按规范化 URL 去重；记录重定向后的 URL 与原 URL 的对应关系。分页指回已访问 URL、重复内容页或没有下一页时终止对应分支。对不同 URL 返回相同内容的情况记录告警，并由页面总量上限兜底。

### 4.2 图片提取

默认范围为页面内所有图片元素，也可指定正文容器排除导航、头像、广告；因此“全部图片”指提取规则覆盖的候选图片。

支持 `img[src]`、配置的懒加载属性（例如 `data-src`、`data-original`）、`picture/source` 与 `srcset`。对同一图片元素按配置的属性优先级选择有效地址，默认在响应式候选中选最大声明尺寸版本，避免把多种缩略尺寸全部下载；可选择保留全部候选。

支持显式配置原图链接选择器及属性，例如 `.image a.original` 的 `href`。不默认下载页面内所有普通超链接。图片域名允许列表独立于页面域名，便于纳入网站 CDN。

详情内容存在多页时，可配置“详情下一页”选择器和每组最大页数；第二阶段访问这些页面并记录与原详情页的分组关系，不能扩展到任意站内链接。

首期仅处理服务端返回的 HTML，不执行 JavaScript。CSS 背景图、脚本动态生成地址、无限滚动和浏览器渲染留到后续；遇到这些页面明确提示能力限制。

## 5. 技术架构

首期建议在现有 Java 后端增加独立采集模块：HTTP 抓取、HTML 解析、队列调度、整理与入库。HTML 解析器建议评估 Jsoup，实施时确认兼容版本与选择器覆盖。暂不增加浏览器容器或 GPU 依赖。

模块职责：

- `CrawlRuleService`：模板、校验、预览和规则快照。
- `CrawlDiscoveryWorker`：列表页遍历与详情链接收集。
- `CrawlPageWorker`：详情页获取、图片提取和详情分页。
- `CrawlDownloadWorker`：受限流式下载、解码校验、哈希与缩略图。
- `CrawlStagingService`：查询、编辑、删除、精确去重与相似组。
- `CrawlImportService`：选择入库、幂等控制及逐项结果。
- `SafeHttpFetcher`：所有出站请求统一经过域名、IP、重定向和资源限制。

使用独立有界工作线程池；任务项、尝试次数和租约写数据库，避免仅靠内存队列或 `@Async` 丢失工作。WebSocket 是进度通知，查询 API 才是状态依据，断线重连后重新读取快照。

## 6. 建议数据模型

| 表 | 关键字段与用途 |
| --- | --- |
| `crawl_sites` | 所有者、网站名称、入口地址、允许域名与采集上限 |
| `crawl_rules` | 所属网站、规则名称、解析选择器、过滤条件与是否生效；每网站最多一条生效 |
| `crawl_jobs` | 所有者、规则快照、阶段、运行状态、停止原因、各类计数、总字节、时间与限制 |
| `crawl_pages` | 任务、类型 LIST/DETAIL、原始及规范化 URL、URL 哈希、父页、详情分组、深度、状态、重试、HTTP 状态、错误、租约 |
| `crawl_seen_pages` | 站点级已发现详情链接历史；任务清理后仍保留，用于手工和每日任务的跨任务增量去重 |
| `crawl_assets` | 任务、图片 URL、URL 哈希、下载/整理状态、本地对象键、MD5、SHA-256、pHash、尺寸、字节、备注、租约、错误 |
| `crawl_image_skips` | 用户永久跳过的规范化图片 URL、首次来源、原因、累计命中次数和最近命中时间 |
| `crawl_asset_sources` | 图片与来源页面的多对多关联、标题、提取属性；同一图片在多个页面出现时保留全部来源 |
| `crawl_import_batches` | 请求幂等键、所有者、状态、入库选择快照、相册/标签策略、结果计数 |
| `crawl_import_items` | 批次、采集图片、状态、目标 photo ID、结果码和错误 |
| `photo_sources` | 正式图库照片与来源页面/图片 URL 的关联，任务清理后仍保留来源 |

索引与约束：页面按任务、类型和规范化 URL 哈希唯一；图片下载项按任务和规范化图片 URL 哈希唯一；来源关联防重复；导入项对同一采集图片的成功入库进行唯一保护。URL 原文仍保存并检查哈希冲突，不能仅以哈希当作完整地址。

精确重复文件按内容哈希分组，首期可保留各下载项独立文件以简化清理；不要过早做跨任务共享物理文件。查询按任务、所有者、状态、创建时间建索引。JSON 用于配置快照，调度和筛选所需字段使用独立列。

数据库变更必须兼顾全新部署和已有 NAS 数据升级；实施时核对现有 schema 初始化方式，为新增表、索引和必要图库哈希约束提供可重复执行的升级脚本。

## 7. 生命周期、恢复与计数

任务采用独立字段：`phase` 为 DISCOVERY / AWAITING_CONFIRMATION / DOWNLOAD / REVIEW；`status` 为 QUEUED / RUNNING / PAUSING / PAUSED / COMPLETED / PARTIAL / FAILED / CANCELLED。`stopReason` 区分耗尽队列、达到上限、用户取消和故障。

列表页、详情页和图片项分别保存 PENDING / RUNNING / SUCCEEDED / FAILED / SKIPPED。工作线程短事务领取条目并设置租约，网络 I/O 在事务外进行，完成时短事务写结果；进程重启后回收过期租约。领取和结果写入使用版本号或租约令牌，防止旧工作线程覆盖新结果。

暂停停止派发新条目，等待在途工作退出后进入 PAUSED；取消尽可能中断请求并清理未完成临时文件。恢复沿用队列和规则快照，已成功项不重复下载。

暂时性连接失败、超时、429、500、502、503、504 会有限指数退避重试，并尊重 `Retry-After`（最长等待 60 秒）；404、类型不符、访问策略拒绝等记录终态。默认最多额外重试 2 次，可在系统设置配置为 0–5 次。重试耗尽的一项不得中断其他项。

计数按阶段分别展示，不把“发现页面数”当成“图片总数”：列表处理、详情发现/选择/处理、图片发现/下载/失败/过滤、精确重复、待整理/已删除/已入库。唯一队列项计算一次，重试次数另计；发现阶段展示已处理量，未知总量不伪造百分比。全部终结后根据失败与停止原因计算完成状态。

## 8. 本地文件与入库一致性

新增配置 `app.storage.crawl-dir`，建议挂载到 NAS 持久化卷的 `crawl/` 子目录。按任务 ID、内部图片 ID 保存下载文件及缩略图，名称由系统生成，不使用远端路径直接拼接磁盘路径。

下载写 `.part` 文件，流式限制字节数，校验真实图片格式、可解码性、像素上限，完成后原子发布到 staging 正式文件名，再更新数据库状态。崩溃遗留临时文件按租约与宽限期清理。首期只开放已验证的栅格图片格式，明确限制单张像素和动画帧数，拒绝 SVG、HTML 伪装和不支持格式。

待整理文件通过受身份认证和所有权检查的接口提供；不直接映射公开静态目录，前端只加载本地缩略图。待整理区删除不调用图库删除接口。

### 8.1 去重策略

URL 去重减少重复请求；下载后 MD5 用于兼容当前图库匹配，SHA-256 用于确认内容身份。命中旧图库 MD5 时应按需读取原图进一步校验，避免把 MD5 命中直接当作不可撤销删除依据。

相似图仅作为人工整理辅助。先明确 pHash 编码与位级汉明距离，再抽取公共实现；不能直接沿用当前服务按字符串字符比较的逻辑而假定适合所有哈希编码。首期以精确去重为必需项，相似图可在下一阶段交付；大批量相似比较应分批或索引候选，避免无界两两比较。

图库已有图片默认跳过新增，可明确选择关联到目标相册。图库回收站已有图片提示恢复入口，不能自动恢复或另建重复项。

### 8.2 选择入库

1. 用户提交采集图片 ID、目标相册/标签及幂等键，后端保存选择快照；“全部筛选结果”在服务端固化 ID，避免筛选随时间变化。
2. 校验所有权、文件完整性、整理状态、目标相册权限；重新检查图库重复，因为预览之后图库可能变化。
3. 逐项准备正式存储文件，通过可恢复的导入状态和目标对象键关联。文件系统与数据库不能作为同一事务提交，失败项保留 staging 原件以便重试。
4. 每项独立事务创建照片、相册/标签关系、来源记录和导入结果；对并发相同内容入库用数据库约束或统一哈希锁保护，所有导入入口必须遵循同一策略。
5. 提交后通过持久化待索引记录触发 AI 索引；AI 失败单独重试，不把已入库照片回滚。任务重启时可重新派发未处理的索引记录。
6. 结果展示成功、失败、跳过重复数及逐项原因；完成后刷新待整理区和图库计数。单项提交失败不影响已提交项，成功项重复请求返回原 photo ID。

入库后才允许清理对应 staging 文件；后台对账以导入记录为依据清理孤立副本，不能删除被图库引用的文件。删除整个采集任务默认只清理采集数据，已入库照片和 `photo_sources` 保留。

## 9. API 草案

统一前缀 `/api/crawl`。批量导入请求只负责持久化批次和逐项快照，实际入库由后台队列执行，前端轮询批次状态；单项事务相互隔离，请求携带幂等键，网络异常后重试不会重复创建图库照片。

| 方法与路径 | 用途 |
| --- | --- |
| `GET/POST /rules`、`PUT /rules/{id}` | 查询、创建、修改规则 |
| `POST /rules/preview` | 受同样访问策略限制的列表/详情规则测试 |
| `POST /jobs` | 创建任务，返回 202 与任务 ID |
| `GET /jobs`、`GET /jobs/{id}` | 分页任务及阶段计数 |
| `GET /jobs/{id}/pages`、`PATCH /jobs/{id}/pages` | 分页搜索链接清单及确认前批量保留/排除 |
| `POST /jobs/{id}/download` | 固化选中详情页并进入第二阶段 |
| `POST /jobs/{id}/pause`、`resume`、`cancel`、`retry` | 状态校验后的控制操作 |
| `GET /jobs/{id}/assets` | 分页待整理图片与筛选 |
| `GET /assets/{id}/thumbnail`、`content` | 经认证的本地预览 |
| `PATCH /jobs/{id}/assets` | 批量修改待整理图片备注 |
| `POST /jobs/{id}/assets/delete`、`restore` | 采集区删除及恢复 |
| `POST /jobs/{id}/import-preview` | 计算新增、重复、已入库和阻止数量 |
| `POST /jobs/{id}/import` | 逐项选择入库，可设置目标相册和标签 |
| `DELETE /jobs/{id}` | 永久清理 staging 文件及任务记录；文件失败时保留记录供重试 |
| `POST /jobs/{id}/similarity` | 按指定位级汉明距离分析并保存相似组 |
| `GET /imports/{id}` | 查询导入批次汇总 |
| `GET /imports/{id}/items` | 分页查询逐项结果，可按状态筛选 |

当前导入创建结果包含 `batchId`、`status`、`success`、`fail`、`skipped`；待整理和导入明细查询返回标准分页结果。修改性接口均校验资源所有权；阶段不匹配返回明确冲突原因。后台执行逐项更新状态，服务中断后从未完成项继续。

## 10. 网络访问与资源边界

这是部署在 NAS 上的服务端 URL 抓取功能，访问控制属于核心实现要求：

- 只接受 HTTP/HTTPS，默认标准端口；拒绝带用户名密码的 URL、回环、内网、链路本地、云元数据、组播和其他非公网地址，包括 IPv6 与 IPv4 映射形式。
- DNS 解析结果、每次重试、每一跳重定向都重新校验；连接必须绑定到已校验地址并保持正确的 Host/TLS 验证，不能校验一次后交给客户端重新解析，防止 DNS 重绑定。
- 规则预览、列表页、详情页、图片、robots 请求统一使用安全抓取入口；跨域图片只允许明确加入的域名。网络层出站策略作为第二层防护。
- 明确全局与每域名并发、请求间隔、连接/读取/总超时、重定向次数、HTML 解压后大小、单图大小、像素数、总图数和磁盘保留空间。
- 系统设置支持多个 HTTP 代理；HTTPS 目标通过 HTTP CONNECT 隧道访问。代理按管理员拖动后的优先级依次尝试，连接异常、代理认证失败或网关错误时切换下一项，再按配置决定是否直连。
- 代理密码使用 AES-GCM 加密后保存，API 只返回“是否已配置密码”。生产环境建议单独配置稳定的 `CRAWLER_PROXY_SECRET`；修改密钥后需要重新录入已有代理密码。
- 首期抓取公开无需登录的页面，提供可识别的 User-Agent，遵循网站 robots 规则；不提供验证码绕过。若 robots 无法确定，展示原因并暂停该站点请求。
- 用户明确指定网站进行外网抓取；本地已有照片、人脸数据及 AI 信息不发送到目标网站。来源 URL 可能含敏感查询参数，日志脱敏，预览 HTML 不直接注入应用页面。

后续若增加浏览器渲染，需要单独隔离容器，并对浏览器全部子资源与重定向执行相同出站策略，不能只校验初始页面 URL。

## 11. 分阶段实施与验收

### 第一阶段：完整可用闭环

交付静态 HTML、规则模板与预览、列表分页、详情页清单确认、逐页图片下载、持久化队列、暂停/恢复/重试、待整理区、精确去重、删除恢复、相册标签整理、选择入库及网络资源限制。

验收场景：

- 有三页列表且链接重叠时，详情页去重并完整枚举，未匹配的站外链接不进入队列。
- 发现阶段结束前不下载详情图片；默认等待链接清单确认，自动继续仅按用户配置执行。
- 相对 URL、懒加载、srcset、CDN、详情分页按规则提取，重复来源仍能追溯。
- 单页 404、单图损坏、下载超时和数据库单项失败不终止其他工作，统计准确。
- 分别在下载中、文件落盘后、数据库提交前后重启，恢复不重复入库，不丢失成功结果。
- 采集区照片不出现在图库、搜索、时间线和人物识别中；选择 3 张只入库这 3 张。
- 同一导入请求重复提交或并发导入重复内容，只产生一份正式照片记录，结果可查询。
- 入库后删除采集任务不删除图库文件；未入库图片删除和恢复正确。
- 回收站已有重复图不会被自动恢复；来源在采集任务清理后仍可查看。
- 达到配额显示不完整原因；磁盘不足停止新下载并保留可恢复状态。
- SSRF、重定向到私网、DNS 重绑定、路径穿越、图片炸弹、未授权访问在自动化测试中被拒绝。

测试使用本地可控 HTTP 测试站点和专用测试网络配置，不依赖真实网站稳定性；生产公网限制不能为了测试被关闭。事务、并发和重启恢复需真实数据库集成测试，不能仅靠 mock 或注解检查证明。

### 第二阶段：整理效率

补充相似图人工分组、重复组保留推荐、规则导入导出、按页面创建相册、增量重新采集以及大数据量性能优化。增量任务与旧任务独立记录，避免旧规则修改导致历史结果改变。

### 第三阶段：复杂网站

按实际站点需求评估浏览器渲染、无限滚动、背景图和需要用户授权的登录会话。先验证少量目标站点，再决定是否引入独立采集服务；首期不承诺任意网站通用抓取。

## 12. 实施顺序与待验证事项

实施顺序：数据库及 staging 存储 → 安全 HTTP 抓取与规则预览 → 两阶段持久化队列 → 待整理区和精确去重 → 幂等入库与来源记录 → 前端联调、恢复和安全测试。

开始实施可沿用本文默认决策，无需先引入额外服务。进入网站适配测试时，应收集一至两个实际目标网站及列表/详情样例，用来验证分页、懒加载、图片 CDN 和是否必须浏览器渲染；这些信息影响适配范围，不影响独立待整理区和选择入库的架构。
