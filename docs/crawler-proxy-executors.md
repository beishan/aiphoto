# 系统代理与爬虫执行器

## 设置入口

管理员在 **系统设置 → 系统代理配置** 中添加普通 HTTP 代理或 Mihomo 代理。普通代理支持用户名和密码；Mihomo 另外配置控制 API 地址及密钥。密码和密钥使用现有 `CRAWLER_PROXY_SECRET` 加密，接口只返回是否已配置，编辑时留空保留原值，勾选清除删除凭据。

**测试连接**分别检测 Mihomo 控制器与实际 HTTP 代理出口，检测目标固定为 `https://www.gstatic.com/generate_204`。不会切换节点。节点延迟检测同样不切换节点，检测成功不保证目标采集网站可访问。

Mihomo 的代理主机/端口必须填写 HTTP 入口，控制 API 地址填写控制器地址，如 `http://192.168.1.10:9090`。Docker 中 `localhost` 指向后端容器自身，跨容器应使用同网络服务名或可达的 NAS IP。

## 执行器

在 **系统设置 → 爬虫设置 → 执行器配置** 中新增或编辑执行器，支持：

- 默认代理池：只包含启用的普通代理，按优先级尝试，遵循全局直连回退配置。
- 直连：显式使用 NAS 网络，不使用 JVM 系统代理。
- 指定普通代理：使用选中的代理，失败不会回退到其他代理或直连。
- Mihomo：选择系统代理、已有 Selector 受控组和有序备用节点列表，不会创建或修改 Mihomo 配置。

每个执行器同时处理一个采集任务，最多 16 个执行器。任务包括网页发现和图片下载；人工导入照片仍使用原有独立流程。没有可用执行器时任务保持排队，定时调度器继续尝试。初次升级建立一个默认执行器；全部停用可停止新任务派发。运行中的执行器不可修改或删除。代理被执行器引用时需先修改执行器解除引用，再修改或删除代理。

Mihomo 支持固定第一个节点、仅故障自动切换、按成功请求数顺序轮换（包含故障切换）。请求数包括 HTML 与图片，不按照片入库数计算；请求内重试、重定向和失败不会增加成功计数。节点列表按用户选择顺序保存。当前节点、请求计数、冷却状态和最近错误持久化，重启后恢复。

同一规范化控制地址和 Selector 只能绑定一个执行器。为执行器建立专用 HTTP 入口和 Selector，并确保入口流量确实经过该 Selector。例如合并到 Mihomo 配置相应区块：

```yaml
proxy-groups:
  - name: 相册爬虫
    type: select
    use:
      - 你的机场提供者名称
listeners:
  - name: photo-crawler
    type: http
    listen: 0.0.0.0
    port: 7895
    proxy: 相册爬虫
```

自动切换仅使用受控组中的已选具体节点，不选择 DIRECT、REJECT 等出口或其他代理组。切换后读取实际节点确认；每次请求关闭专属 HTTP 客户端，避免复用旧节点连接。用户在其他应用中改变节点时，下一次请求重新应用执行器所选节点。

网络连接失败、HTTP 401/403/429/451 和 5xx 会触发节点故障处理；普通 404、URL/域名校验、解析和图片格式错误不冻结节点。先完成现有请求重试，然后冷却异常节点，自动模式尝试下一个可用节点。控制 API 失败不冻结节点，采集任务暂停并保留进度；所有节点冷却时同样暂停，待控制器恢复或冷却到期后在任务列表手动继续。节点尚未全部冷却且所有候选尝试失败时，沿用现有页面/图片失败记录。

当前执行器占用与节点控制面向**单实例后端**；不要让多个后端实例或不同地址别名同时管理同一 Selector。

## 升级

版本 `0.11.0` 的增量 SQL 位于 `backend/src/main/resources/schema.sql`，后端启动时幂等执行。旧代理自动视为普通 HTTP 代理，旧采集规则和任务保留。重新构建并启动后端与前端即可使用新设置。
