# 系统代理与爬虫执行器

## 设置入口

管理员在 **系统设置 → 系统代理配置** 中添加普通 HTTP 代理或 Mihomo 代理。普通代理支持用户名和密码；Mihomo 另外配置控制 API 地址及密钥。密码和密钥使用现有 `CRAWLER_PROXY_SECRET` 加密，接口只返回是否已配置，编辑时留空保留原值，勾选清除删除凭据。

**测试连接**分别检测 Mihomo 控制器与实际 HTTP 代理出口，检测目标固定为 `https://www.gstatic.com/generate_204`。不会切换节点。节点延迟检测同样不切换节点，检测成功不保证目标采集网站可访问。

Mihomo 的代理主机/端口必须填写 HTTP 入口，控制 API 地址填写控制器地址，如 `http://192.168.1.10:9090`。Docker 中 `localhost` 指向后端容器自身，跨容器应使用同网络服务名或可达的 NAS IP。

## 网站测试与基本信息

0.15.0 起，在 **采集中心 → 采集网站 → 网站配置** 及新增网站弹窗中，单独选择“测试与网站信息使用的代理”：

- 系统默认代理策略：保留升级前行为，使用已启用的普通 HTTP 代理池及系统直连回退设置。
- 直连：仅使用后端所在机器的网络。
- 指定代理：从系统设置中的 HTTP 或 Mihomo 代理中选择一个已启用入口；失败不会改用其他代理或直连。Mihomo 使用配置的 HTTP 入口，不调用控制 API 切换节点。

“测试规则”使用当前表单选中的代理，列表页和样例详情页保持同一网络配置；保存网站后，该选择持久化。旧客户端未传入临时代理选择时使用网站已保存配置。

“获取网站信息”使用当前起始 URL、域名黑名单和代理草稿读取网页标题、简介及最终 URL，不创建采集任务、不保存网站；名称为空时将标题填入名称。黑名单留空默认允许所有公网域名，填写后同时禁止其子域名。网站或代理修改后显示结果会清空。代理列表仅包含名称、类型、启用状态和 ID，不返回地址或凭据。

这些请求不会占用执行器、触发节点轮换或更新执行器计数、冷却和错误记录。实际网页发现、每日扫描和图片下载继续使用执行器自己的网络策略。已停用或已删除的指定代理会明确报错，需重新选择；升级通过幂等 SQL 增加网站代理方式及代理 ID 两个字段。

## 发现页配置

0.16.0 起，网站配置将“网站入口”和“发现页入口”分开：网站入口供获取标题和简介，发现页入口供扫描详情链接。旧多行发现页配置最多 20 个入口，0.17.0 起迁移为独立扫描页。当前在网站配置弹窗的「扫描页」标签管理入口。0.18.0 起域名无需加入白名单，但不能命中网站黑名单，且实际请求仍限于公网 HTTP/HTTPS 标准端口。

保存网站后，手动扫描及每日扫描都从这些入口建立队列，继续使用生效解析规则中的详情链接选择器、过滤条件和下一页选择器。所有入口和翻页共享“列表页”总上限；上限小于入口数量时仅处理队列前面的页面。普通入口处理失败不阻断其余入口，执行器控制故障仍暂停任务。

测试规则仅预览首个发现页及其中首个详情页，使用网站测试代理；获取网站信息仍使用网站入口。实际扫描继续由执行器选择代理。发现页配置保存在任务快照中，修改网站不改变已创建任务；升级前的任务快照继续使用原起始页。

## 执行器

在 **系统设置 → 爬虫设置 → 执行器配置** 中新增或编辑执行器，支持：

- 默认代理池：只包含启用的普通代理，按优先级尝试，遵循全局直连回退配置。
- 直连：显式使用 NAS 网络，不使用 JVM 系统代理。
- 指定普通代理：使用选中的代理，失败不会回退到其他代理或直连。
- Mihomo：选择系统代理、已有 Selector 受控组和有序备用节点列表，不会创建或修改 Mihomo 配置。

每个执行器同时处理一个采集任务，最多 16 个执行器。任务包括网页发现和图片下载；人工导入照片仍使用原有独立流程。没有可用执行器时任务保持排队，定时调度器继续尝试。初次升级建立一个默认执行器；全部停用可停止新任务派发。运行中的执行器不可删除；0.12.0 起支持请求边界更新策略。代理被引用时修改连接地址或删除前需先解除引用，名称、凭据和启用状态可单独更新。

Mihomo 支持固定第一个节点、仅故障自动切换、按成功请求数顺序轮换（包含故障切换）。请求数包括 HTML 与图片，不按照片入库数计算；请求内重试、重定向和失败不会增加成功计数。节点列表按用户选择顺序保存。当前节点、请求计数、冷却状态和最近错误持久化，重启后恢复。

同一规范化控制地址和 Selector 只能绑定一个执行器。为执行器建立专用 HTTP 入口和 Selector，并确保入口流量确实经过该 Selector。例如合并到 Mihomo 配置相应区块：

```yaml
proxy-groups:
  - name: 相册爬虫
    type: select
    use:
      - 你的机场提供者名称
listeners:
  - name: photo-crawler
    type: http
    listen: 0.0.0.0
    port: 7895
    proxy: 相册爬虫
```

自动切换仅使用受控组中的已选具体节点，不选择 DIRECT、REJECT 等出口或其他代理组。切换后读取实际节点确认；每次请求关闭专属 HTTP 客户端，避免复用旧节点连接。用户在其他应用中改变节点时，下一次请求重新应用执行器所选节点。

网络连接失败、HTTP 401/403/429/451 和 5xx 会触发节点故障处理；普通 404、URL/域名校验、解析和图片格式错误不冻结节点。先完成现有请求重试，然后冷却异常节点，自动模式尝试下一个可用节点。控制 API 失败不冻结节点，采集任务暂停并保留进度；所有节点冷却时同样暂停，控制器恢复后在任务列表手动继续；0.12.0 起冷却到期或解除人工冻结会自动恢复等待任务。节点尚未全部冷却且所有候选尝试失败时，沿用现有页面/图片失败记录。

当前执行器占用与节点控制面向**单实例后端**；不要让多个后端实例或不同地址别名同时管理同一 Selector。

## 升级

版本 `0.11.0` 的增量 SQL 位于 `backend/src/main/resources/schema.sql`，后端启动时幂等执行。旧代理自动视为普通 HTTP 代理，旧采集规则和任务保留。重新构建并启动后端与前端即可使用新设置。

### 轮换计数

- 成功请求数：完整获取一份 HTML 或图片响应才计数，重定向和请求内重试不单独计数。
- 成功详情页数：完成一个来源链接及其详情分页后计数，不包含列表扫描。
- 成功图片数：图片下载、校验、写入暂存并保存记录后计数；跳过或下载失败不计数。
- 成功任务数：图片下载阶段全部成功后计数；列表发现、人工确认、导入和部分失败任务不计数。
- 页面、图片和任务计数通过数据库回执去重，重复处理同一任务资源不重复计数。
- 时间只累计采集请求、限速等待与重试时间，解析、空闲、停机和人工冻结不计入。控制 API 失败的请求不增加时间。

轮换策略改变或成功切换节点后重置轮换计数；各节点的连续异常与冻结状态独立保留。随机轮换至少有两个可用候选时不立即重复当前节点。

### 故障与恢复

Mihomo 的同一请求在当前节点至少尝试两次，重试耗尽后记一次异常；开启故障切换时，本轮只尝试每个所选节点一次。达到连续异常阈值才冻结节点。普通代理的异常在一次完整请求结束后合并计数，重复重试不会重复冻结；成功连接其他代理后仍保留原异常记录。

所有可用节点/普通代理冻结后，任务进入带“执行器等待”原因的暂停状态，进度和待处理资源保留；冷却到期由调度器自动恢复。人工冻结同样等待，解除后自动恢复。用户主动暂停、取消的任务不会被等待恢复调度器自动启动。控制 API 不可用、受控组变更或节点切换无法确认时仍需修复配置并手动继续，不能把控制器错误归入节点异常。

节点重试失败后换节点成功时，执行详情保留原节点错误及最终成功记录。运行计数、错误、等待原因、节点异常、冷却和切换事件持久化。

### 配置更新与引用保护

运行中允许更新名称、描述、启用和采集策略；当前请求、重试和故障切换使用原配置，下一次请求读取最新配置。更换 Mihomo 控制器、受控组或入口前需先冻结并等待当前任务暂停，保证同一 Selector 不被多个执行器同时管理。绑定节点组不可直接编辑或删除，先解除执行器引用。

系统代理被引用时允许更新名称、凭据或启用状态，运行时读取最新密钥；代理类型、控制地址和 HTTP 入口改变需解除引用。普通指定代理支持单独停用某个代理，其他启用代理继续提供采集。

应用不会自动创建 Selector、修改机场订阅、更新 Mihomo 配置或清空其他应用的连接。仍以单实例后端管理 Selector。新版 schema 增加节点组、执行详情、计数回执和扩展策略，后端启动时自动执行；部署时需同时更新后端和前端。


## 0.13.0 系统代理配置对齐

| ai-book 功能 | 本项目实现 |
|---|---|
| 名称、代理地址、普通/Mihomo 类型、启用与优先级 | 完整 HTTP 地址输入，拖动、按钮和上下方向键排序；兼容已有主机/端口配置 |
| 控制 API 地址与密钥留空保留/清除 | 已支持；凭据加密保存，列表只显示是否配置 |
| 保存前测试控制 API 与代理有效性 | 普通代理和 Mihomo 均可测试当前草稿；独立显示控制与出口结果；无需先保存 |
| 全部具体节点和协议搜索 | 已支持，过滤分组与内置直连/拒绝节点 |
| 节点延迟、检测时间与可用状态 | 初始读取 Mihomo 历史，手动检测刷新；失败立即标记，延迟使用 300/600 ms 颜色区间 |
| 节点组双栏选取、批量加入/移出、轮换顺序 | 已支持；最多 100 个成员，只允许受控 Selector 内具体节点 |
| 独立节点组入口、编辑和删除 | 已支持；沿用系统代理认证，执行器引用期间继续保护 |

当前系统代理是本项目执行器复用的代理资源。保持现有数据表和请求路由模型，不复制 ai-book 的独立爬虫代理引用表。实际入口沿用 Java 爬虫的 HTTP CONNECT 支持；不会把 HTTPS 或 SOCKS 入口当作 HTTP 入口保存。Mihomo 控制 API 可使用 HTTP/HTTPS。检测记录展示控制器返回历史和当前面板本次检测结果，未新增本地长期检测日志。
