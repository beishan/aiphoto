# 独立扫描页与采集队列（0.17.0）

参照本地 aibook 的发现页管理、周期扫描、单条采集和任务抽屉，将图片采集流程拆为独立阶段。

## 使用流程

1. 在「网站与规则」配置生效的解析规则。域名配置为「不允许访问的域名」黑名单，留空默认允许所有公网域名。
2. 打开采集网站的配置弹窗，在与「网站设置」「解析规则」并列的「扫描页」标签中添加多个入口。仅展示和管理当前网站的扫描页；每个入口独立设置自动扫描开关、扫描周期（5–10080 分钟）和列表页上限（1–1000）。手动点击「扫描」创建扫描任务。
3. 扫描任务只发现图片详情页 URL，沿列表翻页规则继续发现；每个新链接立即写入清单，以网站和规范化 URL 去重。
4. 在「采集页面」查看全部扫描结果，支持网站、URL 搜索及仅待采集筛选。每条 URL 前的「采集」按钮创建一个独立采集任务，重复点击返回同一任务。已创建任务显示「查看任务」。
5. 在「采集队列」查看网站队列。管理员可创建执行器并为网站同时选择多个执行器，一个执行器同时处理一个任务；停用或冻结后不接收新任务。网站没有专用执行器时使用共享执行器池；系统尚未配置任何执行器时使用共享的默认执行器，并发为 1。
6. 在「采集任务」或队列任务列表点击任务，以侧边抽屉查看进度、页面、下载图片数和错误。采集完成后进入原有待整理、去重与入库流程。

扫描与采集任务均经过现有持久化队列、租约和执行器调度。调度检查默认每 10 秒执行，自动扫描检查默认每 60 秒执行。同一扫描入口已有排队、运行或暂停任务时不会重复创建。

## 兼容升级

- 启动时 `schema.sql` 自动为已有网站将旧多行入口迁移为独立扫描页，仅迁移一次，删除的扫描页不会在重启后恢复。
- 原网站每日扫描转换为每个入口的 1440 分钟周期，并关闭旧网站级每日扫描，保留首次到期时刻；此后采用入口自己的周期。
- 旧任务发现的页面也会出现在「采集页面」。已经进入旧下载阶段的页面关联原任务，不能重复创建任务；尚未下载的页面可以逐条发起采集。
- 单个 URL 任务使用创建时的网站生效规则快照。采集任务清理后，对应发现页面恢复可采集；已入库的照片仍保留。
- 单页解析成功但部分图片失败时，重试会重新访问该页，跳过已经下载的图片，只重试失败内容。

## 域名黑名单（0.18.0 起）

- 使用 `blockedHosts` 字段，多个域名可用逗号或换行分隔；填写域名本身，不包含协议、端口或路径。
- 黑名单包含指定域名及其子域名，例如 `66img.cc` 同时禁止 `cdn.66img.cc`，不会影响 `other66img.cc`。
- 页面、原图和每次 HTTP 重定向均会检查黑名单；仍禁止访问内网、回环、链路本地等非公网地址。
- 升级时新黑名单默认为空，旧白名单不会反转为黑名单。旧任务快照中的 `allowedHosts` 字段被忽略，因此旧任务重试也不再因缺少图床白名单而失败。
- 新任务将当前黑名单保存进规则快照；更改网站配置不会覆盖已创建任务的规则快照。

## 接口

| 方法 | 路径 | 用途 |
|---|---|---|
| GET / POST | `/api/crawl/scan-pages` | 查询 / 创建扫描入口 |
| PUT / DELETE | `/api/crawl/scan-pages/{id}` | 编辑 / 删除扫描入口 |
| POST | `/api/crawl/scan-pages/{id}/scan` | 创建扫描任务 |
| GET | `/api/crawl/collection-pages` | 分页查看跨任务发现结果 |
| POST | `/api/crawl/collection-pages/{id}/collect` | 幂等创建单 URL 采集任务 |
| GET | `/api/crawl/queues` | 网站队列、并发和执行器摘要 |
| PUT | `/api/crawl/queues/{siteId}/executors` | 管理员调整网站执行器列表 |

所有扫描页、发现页面和任务接口按当前用户验证归属，执行器配置沿用管理员权限。
