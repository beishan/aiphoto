# AI 模型安装与验收（0.11.0）

## 安装模型

AI 服务仍只从挂载的 `/models` 目录推理，不会在启动时下载权重。`AI_MODELS_PATH` 指向 NAS 宿主机的模型目录，后端和 AI 服务必须挂载同一个目录。

在设置 → 模型管理 → 在线下载中，可以下载 Chinese-CLIP ViT-B/16、InsightFace buffalo_l 和 YOLOv8n/s。下载完成后点击“设为当前模型”：后端会安装文件，向 AI 服务发送配置，并检查真实加载结果。只有成功加载后任务才显示已安装；激活失败会保留错误信息，可以修正后再试。

下载文件位于 `.downloads`，安装结果位于 `installed/<任务 ID>/`，不会覆盖正在使用的模型。任务列表目前保存在内存中，后端重启后任务列表会清空，已安装模型和 AI 配置文件仍然保留，可以从“本地模型”配置原路径。

也可手动安装以下默认布局：

```text
模型根目录/
├── chinese-clip/clip_cn_vit-b-16.pt
├── insightface/models/buffalo_l/
│   ├── det_10g.onnx
│   ├── w600k_r50.onnx
│   └── 其他 buffalo_l ONNX 文件
├── ultralytics/yolov8n.pt
└── blip2/
    ├── config.json
    ├── preprocessor_config.json
    ├── tokenizer_config.json
    ├── tokenizer 所需的词表等文件
    └── 全部模型权重及分片索引
```

- CLIP 目前支持与数据库 512 维向量一致的 Chinese-CLIP ViT-B/16 官方 checkpoint。可以配置自定义文件名，但文件必须具有正确的 `state_dict` 和模型架构；`open_clip_pytorch_model.bin` 不能靠重命名变成兼容权重。切换到不同架构或维度需要另外设计向量重建与数据迁移，不能直接切换。
- InsightFace 路径需要采用 `<root>/models/<模型名>` 结构，并具备检测和识别模型。
- YOLO 使用目标检测 `.pt` 权重；分类专用模型不提供目标框，因此会被明确拒绝。
- BLIP-2 默认禁用。准备完整的本地 Hugging Face 模型目录后，在“本地模型”页启用并保存。仅上传一份 `.bin` 不足以安装 BLIP-2；缺文件时会显示具体错误。推理默认生成模型支持的描述，不保证中文输出。
- OCR 和内容安全尚未接入推理；界面会明确显示暂未支持。重复照片检测是内置哈希功能，无需下载模型。

官方模型来源：[Chinese-CLIP](https://github.com/OFA-Sys/Chinese-CLIP)、[InsightFace 模型包](https://github.com/deepinsight/insightface/releases/tag/v0.7)、[Ultralytics 权重](https://github.com/ultralytics/assets/releases/tag/v8.2.0)。

## 索引与重试

索引按向量、人脸、标签、描述分别保存结果和完成标记。一个模型未配置或推理失败时，其他已启用模型继续分析；禁用模型不会调用。任务结果记录失败阶段，“全部索引”会筛选已启用模型中未完成的阶段，重试不会重复插入人脸、修改人工标签或累计人物照片数。

旧数据中已有的人脸会保留原有分配。迁移会按不同照片重算人物数量，但不会自动删除历史重复的人脸记录。旧数据无法判断“没有人脸/没有目标”是否已分析，因此首次补索引可能再运行一次相关检测。

上传任务在事务提交后启动。新上传、采集入库和新建扫描目录中的照片保存触发用户 ID，人脸阈值使用该用户的设置；历史照片没有用户信息时，手工“全部索引”使用发起用户的设置，其他历史后台导入使用默认阈值。

搜索、人脸和相册训练的阈值都按相似度理解：数值越大，匹配越严格。语义搜索保留原始中文查询。训练相册先计算样本向量的平均原型，再一次检索所有满足相似度的照片，并排除已在相册的照片；这是原型匹配，并非模型微调。

视频取中间代表帧，无法读取中间帧时回退到首帧。所有模型使用同一抽帧规则，便于保持坐标一致。当前结果代表这一帧，不代表对整段视频的全时段分析；图片按 EXIF 方向统一解码。

## GPU 与验收

开发 Compose 的 GPU 声明默认关闭。在具备 NVIDIA Container Toolkit 的宿主机上，可用：

```bash
docker compose -f docker-compose.yml -f docker/docker-compose.gpu.yml up -d --build
```

Jenkins 部署继续使用既有 `ENABLE_GPU` 参数。模型驻留数量由 `AI_MAX_LOADED_MODELS` 控制，默认一份；根据实际显存选择数量，BLIP-2 的额外显存需求需要单独评估。

部署后建议使用独立测试图片和视频依次检查：

1. `/models` 中模型路径、启用状态、错误信息与真实加载状态。
2. 图片、视频索引，人物、动物、食物和植物分类，以及启用 BLIP-2 后的描述。
3. 暂时禁用一个模型，确认其他阶段继续成功；重新启用后补索引，确认成功阶段不重复。
4. 使用 80% 与较低相似度检索，确认更高阈值收窄结果。
5. 用多张样本训练相册，确认新增全部符合阈值的照片；再次训练不产生重复关联。
6. 模型激活失败时确认旧配置保留，随后修复文件并再次加载。

本次代码验证包括 61 项后端测试、9 项 AI 服务回归测试、前端类型检查与生产构建、开发 Compose/GPU 覆盖配置解析。AI 测试使用模型替身并实际验证图片解码与视频抽帧；真实权重推理、PostgreSQL 迁移执行及容器 GPU 可见性仍需在部署环境验收。
